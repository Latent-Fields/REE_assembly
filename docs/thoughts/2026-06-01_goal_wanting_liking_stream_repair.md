# Goal / wanting / liking stream repair: object-bound incentive salience before z_goal

Date: 2026-06-01

## Raw idea

REE does not yet reliably turn "that was good" into "I want that object/cue/outcome
again" into a persistent, consumer-readable z_goal.

Current architecture is too close to:

    benefit pulse -> write current z_world into z_goal -> use z_goal proximity as wanting

The missing chain is closer to:

    contact / cue / object encounter
      -> benefit or liking pulse
      -> object/resource identity binding
      -> incentive salience / wanted-object token
      -> z_goal candidate or goal pointer
      -> persistent goal maintenance
      -> consumer readout by dACC / E3 / commitment
      -> pre-consummatory approach bias

Recent results: 626 (formation did not reproduce), 514k (no wanting/liking dissociation),
625 (event without consumer input), 623 (positive control: signal -> behaviour works).

Before building the elaborate mature goal ecology, REE first needs a minimal
object-bound incentive-salience pipeline that can turn a known benefit event into a
persistent, consumer-readable wanted-object signal.

See intake memo for the structured analysis, the 626 harness-bug finding, and the
diagnostic ladder.
