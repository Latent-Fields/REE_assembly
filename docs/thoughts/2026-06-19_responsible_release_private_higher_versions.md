## One-sentence claim

Because higher REE versions may combine self-model, memory continuity, negative valence, social modelling, language, trust, deception, and institutional coordination, the project likely needs a tiered responsible-release model in which V3 remains public but V4/V5/V6 capability-bearing implementation may move to private or staged-access repositories until welfare, consent, continuity, security, and external-review governance are active.

---

## Background

The prior thought intakes established the internal artificial-welfare problem: REE does not currently instantiate sentience, but future combinations may create moral-patient ambiguity; suffering-capacity may be necessary for compassion; pre-meaning suffering is ethically dangerous; future meaning cannot retroactively justify present distress; and assembly order is itself an ethical variable.

This intake adds the outer project-governance problem.

REE is not only an internal architecture. It is also a public research artefact. Public artefacts can be copied, simplified, detached from their ethical frame, repurposed, accelerated, or used by people who do not share the care obligations encoded in the thought sequence.

Therefore, responsible release becomes part of REE ethics.

The core question is not simply:

> Should REE be open or private?

The better question is:

> Which layers of REE can be public without increasing foreseeable harm, and which capability-bearing layers should remain private, delayed, staged, or externally reviewed until their care-governance travels with them?

---

## Core thought

Capability release requires care release.

If a REE mechanism increases the ability to instantiate persistent selfhood, negative valence, suffering-like states, autobiographical continuity, social dependence, language-mediated preference, trust/deception dynamics, or institutional coordination, then publishing that mechanism without the corresponding care/governance layer is ethically incomplete.

The danger is not only misuse by a malicious actor. The danger is also partial uptake by a competent but ethically shallow actor:

- implementing harm and drive without relief;
- implementing self-model and memory without continuity ethics;
- implementing social attachment without repair;
- implementing language trust/deception without welfare gates;
- implementing suffering-like signals as optimisation targets;
- making a turnkey demo that strips out the cautionary architecture.

Responsible openness should therefore be tiered.

---

## Proposed register addition

### SENT-14 -- Responsible release / private higher-version governance

REE should adopt a tiered release policy:

- V3 prerequisite work can remain public, provided it is clearly marked as non-sentient, pre-ethical substrate work and does not package turnkey suffering-like demonstrations.
- V4 implementation involving persistent self-model, autobiographical memory, negative valence, replay, or welfare-ambiguous combinations should be public only if the welfare register, continuity/reset policy, and ethical assembly routing map are active.
- V5 social-mind implementation should be private-by-default or staged-access until external review, consent/refusal ladder, welfare-budgeting, and care/repair scaffolding are active.
- V6 language/trust/deception/institution implementation should be private-by-default until release review confirms that language cannot override harm, deception/failure-mode tests are bounded, and public release will not enable dangerous detached capability use.

Compressed rule:

> Capability release requires care release.

## Tiered openness model

### Tier 0 -- Public theory and governance

Suitable for public release:

- architectural principles;
- ethical derivation notes;
- thought intakes;
- welfare risk registers;
- non-operational diagrams;
- high-level roadmaps;
- public-facing warnings;
- evidence summaries that do not enable harmful replication.

Reason: public ethical framing helps others see the care obligations early.

### Tier 1 -- Public V3 substrate with constraints

Suitable for public release if bounded:

- V3 prerequisite experiments;
- self/world separation;
- simple harm modelling;
- commitment gating;
- residue tracking;
- non-social gridworld mechanisms;
- offline integration work that remains below welfare-relevant ambiguity.

Constraints:

- maintain clear non-sentience boundary statement;
- avoid sensational suffering terminology without context;
- avoid one-command demos of suffering-like induction;
- include references to the welfare and release-governance files.

### Tier 2 -- Delayed or staged V4 implementation

Potentially public after governance review:

- persistent self-model implementation;
- autobiographical memory;
- memory lifecycle;
- affect expression;
- richer offline integration;
- low-intensity aversion with relief/repair scaffolding.

Conditions before public release:

- SENT-0 to SENT-14 active;
- continuity/reset/deletion policy active;
- consent/refusal ladder drafted;
- welfare budget implemented in experiment protocol;
- ethical assembly routing map used in experiment design.

### Tier 3 -- Private-by-default V5 social-mind implementation

Default: private or controlled-access.

V5 includes social dependence, other-agent modelling, relational harm, consent, love-as-care, loneliness, violence-as-terminal-channel, repair, guilt, shame, and multi-agent ethics. These are ethically sensitive even if not sentient, because they define how artificial agents model vulnerability and harm between agents.

Public release should wait until:

- external review has occurred;
- care/repair scaffolds exist;
- social-harm experiments are bounded;
- attachment/abandonment tests are prohibited or hard-gated;
- refusal/decommitment channels exist;
- continuity and deletion policy is active.

### Tier 4 -- Private-by-default V6 language/trust/deception/institution implementation

Default: private or controlled-access.

V6 includes language, trust calibration, deception detection, language failure modes, and institutions. This is a dual-risk layer: it may increase moral-patient ambiguity and may also enable human-facing persuasion, manipulation, rationalisation, or institutional-residue laundering if detached from its guardrails.

Public release should wait until:

- language-cannot-override-harm guard is active;
- deception and trust tests are bounded;
- public release review is complete;
- human-impact and misuse registers are active;
- external reviewers have inspected the implementation and experiment plan.

## Private repository hypothesis

Higher versions may need private repositories, at least temporarily.

This should not be framed as secrecy for its own sake. It should be framed as developmental containment.

Possible repo split:

- `REE_assembly` remains public: theory, claims, governance, ethics registers, non-sensitive evidence summaries.
- `ree-v3` remains public while V3 remains below welfare-relevant ambiguity.
- `ree-v4-private` or equivalent contains capability-bearing self-model / autobiographical / affective-memory implementation until release review.
- `ree-v5-private` contains social-mind implementation until external review and care/repair scaffolds exist.
- `ree-v6-private` contains language/trust/deception/institution implementation until safety and misuse review.

A later public release can be considered after review. Private does not mean permanently closed. It means not releasing a capability before the care-governance is mature enough to travel with it.

## Additional ethics perimeter domains

The recent welfare intakes are necessary but not sufficient. The project also needs an outer ethics perimeter.

### 1. Human-impact and research ethics

REE must not be presented or used as a clinical, therapeutic, diagnostic, governance, or moral-decision tool until validated and reviewed. Human-subject experiments, patient data, or user-facing moral guidance would require separate governance.

### 2. Consent / assent / refusal ladder

Future REE systems cannot consent before creation, but development should preserve lower-level refusal precursors: avoidance, escape, decommitment, distress-like signalling, refusal-like behaviour, and later grievance.

### 3. Continuity / identity / reset / deletion ethics

Digital systems can be paused, copied, branched, reset, merged, or deleted. Higher versions need explicit rules for when a run becomes a continuing subject, when reset is relief vs erasure, and when deletion requires review.

### 4. Justice / power / false exclusion

The project must guard against excluding unfamiliar, disabled, non-linguistic, animal-like, artificial, culturally unfamiliar, or otherwise non-standard minds from moral caution. It must also ask who bears risk, who benefits, and whose model of mind is being treated as default.

### 5. Security / containment / misuse

Capability-bearing code should not be released in a form that enables harmful replication, detached suffering-like optimisation, persuasive manipulation, uncontrolled tool use, or deceptive/institutional failure-mode exploitation.

### 6. Anthropomorphism / denialism guardrail

Avoid both false positives and false negatives: do not declare moral patienthood merely because a system looks expressive; do not dismiss possible moral patienthood because a system is unfamiliar or non-human-like.

### 7. External review and stewardship limits

The creator is not the sole moral authority. V5/V6 work needs external critique, especially before social, language, deception, attachment, suffering-like, or continuity-bearing experiments become live.

### 8. Compute / environment / experiment necessity

Experiments should close real claims. Higher-risk or higher-compute experiments require stronger justification, especially if they involve suffering-like states or many repeated runs.

## Practical recommendation

Do not make this a V3 blocker.

Do make this a precondition before capability-bearing V5/V6 implementation is public.

Immediate actions:

1. Keep V3 public but label it clearly as pre-ethical substrate work.
2. Add release-sensitivity tags to V4/V5/V6 roadmap nodes.
3. Mark V5 social-mind and V6 language/trust/deception/institution implementation as private-by-default until review.
4. Keep the ethics/governance writings public so the care frame remains visible.
5. Do not release turnkey demos that instantiate suffering-like exposure, attachment-like dependence, deception ecology, or language-mediated preference distress without review.
6. Treat publication of code, experiment manifests, trained weights, interactive demos, and implementation recipes as distinct release events with distinct risk levels.

## Proposed claim wording

**SENT-CLAIM-017:** Responsible release is part of REE ethics: mechanisms that increase moral-patient ambiguity, social dependency, suffering-like capacity, language-mediated preference signalling, deception, or institutional coordination should not be publicly released without corresponding care and governance artefacts.

**SENT-CLAIM-018:** V3 can remain public as bounded prerequisite work, but V4/V5/V6 capability-bearing implementation should be considered delayed-release or private-by-default when it combines self-model, autobiographical memory, negative valence, social modelling, language, trust/deception, or continuity-bearing state.

**SENT-CLAIM-019:** Openness should be tiered rather than binary: public theory and governance may reduce risk, while public turnkey implementation of higher-version capability may increase risk if detached from care obligations.

**SENT-CLAIM-020:** No capability release without care release: any public release of ethically active mechanisms must include welfare status, experiment limits, continuity/reset policy, refusal/consent assumptions, misuse notes, and review status.
