# Object-vector cells: a real object code, but the wrong axis

Høydal, Skytøen, Andersson, Moser and Moser (2019) reported a functional cell class in the medial entorhinal cortex (MEC) that fires whenever the animal is at a particular **distance and direction from a discrete object** — object-vector cells. The striking property is generalisation: a given cell is tuned *equally* to a whole spectrum of objects, from point-like markers to extended surfaces, irrespective of where the object sits in the arena. The cells are dissociable from grid cells (which reference a distal frame) and from border and head-direction cells. The authors argue that vector coding to objects is a predominant form of position coding in MEC.

For REE this paper does two jobs, one supportive and one cautionary, which is why I score it **mixed**. The supportive job: it is among the strongest single-unit evidence that the mammalian brain reserves dedicated machinery for **objects as first-class representational entities** — exactly ARC-006's commitment that entities are sparse, persistent, bindable structures with their own coding scheme rather than incidental bundles of features. The existence of a cell type whose entire job is "an object is *here* relative to me" is a direct neural witness that object-anchored representation is real and worth a substrate.

The cautionary job is more important for getting MECH-045 right, and it sharpens the type-vs-token-vs-anchor fork rather than dissolving it. Object-vector cells code a **vectorial relation** (egocentric distance, allocentric direction) to an object, and they do so **object-generically** — the same cell fires for *an* object at that vector, not for *this particular* object as opposed to that one. In ARC-080's three-store taxonomy this lands squarely on the **WHERE / anchor axis** — the SD-039 ghost-goal-bank lineage — and *not* on the token KEY that MECH-045 requires. If REE modelled its token identity on object-vector coding, it would build a richer where-signal and reproduce the anchor-keyed gap, not close the token-instance gap. The paper is therefore partly evidence for what MECH-045 is *not*: it shows the brain has an object code that generalises across instances, whereas MECH-045 needs one that *distinguishes* instances and follows one through motion.

Caveats compound this. The code is allocentric and spatial; REE's z_world is not an explicit spatial-vector representation, so the correspondence is **structural, not mechanistic** — the very "structural-analogy-no-mechanism" trap that the 641a coherence diagnostic was redesigned to avoid. And the recordings are rodent foraging with physical objects in open fields; nothing in the paradigm demonstrates that a single object's *identity* is tracked through occlusion or re-bound after it moves. I tag MECH-045 alongside ARC-006 only because the paper bears on where the object-file's spatial-anchor coupling would sit (the memo proposes the token buffer *consume* an anchor channel), not because it evidences the token buffer itself. Confidence 0.66, mapping fidelity deliberately held at 0.5: a top-tier source that grounds object-relative coding while warning us off the wrong axis.
