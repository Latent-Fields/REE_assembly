# Data association (DeepSORT): the engineering recipe for the token KEY

The biology in this review tells us *what* a token-instance object file does — bind features across motion, persist through absence, key on continuity not category. None of it tells us the *update rule*. Wojke, Bewley and Paulus (2017) do, and almost embarrassingly directly. DeepSORT solves multi-object tracking by **data association**: a Kalman filter predicts where each existing track should be next; incoming detections are matched to tracks by a cost that combines a **Mahalanobis motion gate** (spatiotemporal continuity) with a **cosine distance in a learned appearance-embedding space**; detections that match nothing **birth** a new track, and tracks that go unmatched for too long **age out and die**. Adding the appearance term to motion-only SORT is what lets tracks survive long occlusions and cuts identity switches sharply.

That predict → gate → match → birth/death loop *is* MECH-045's token KEY, stated as an algorithm. Each track is a persistent **instance pointer** carrying **no category label** — track #7 is just "the thing we have been following," exactly Pylyshyn's label-free index made computational. And the track's stored appearance embedding is, for free, the **per-token feature buffer** the claim asks for. The translation to REE is almost a variable rename: substitute **z_world** for the appearance descriptor, run the same association over a grid-world's entities, and you have a token-instance object-file buffer whose continuity is spatiotemporal + featural and whose identity has no type tag. The paper even hands over the experiment's instrumentation: the **identity-switch count** and track purity are the natural quantitative readouts for persistence, and the paper's own **appearance-vs-motion ablation** is the methodological template for REE's intact-vs-shuffled-identity arms.

But the discounts are exactly where REE's hard problems live, so this entry is as much a map of the risks as an endorsement. First, DeepSORT's appearance metric is **supervised** — a deep embedding pre-trained on a large *person re-identification* dataset with identity labels. REE has no labelled identity data; it must do association over **unsupervised z_world**. If z_world is not discriminative enough — and the 2026-06-06 cluster autopsy established z_world at dim=32 *lacks discriminative granularity*, with E2WorldForward hard-asserting world_dim ≥ 128 — then the appearance term degenerates and association silently falls back to motion-only. Motion-only association is precisely the **location-collapse vacuity mode** in another costume: it would track "whatever was nearest last tick" and pass a naive persistence test without ever re-identifying anything. This is the single most important constraint the design memo carries forward from this paper. Second, DeepSORT **assumes a detector** proposing boxes every frame; REE has no detector, so "what is a trackable entity this tick" (figure-ground / candidate proposal) is a genuine upstream dependency, not something the buffer can assume away. Third, tracking-by-detection associates everything uniformly — it has no notion of **value, attention-gating, or precision**; MECH-045's attention-gated, precision-weighted continuity is an *addition* to the recipe, the part REE must design rather than borrow. Confidence 0.70: the mechanism is the proposal almost verbatim (mapping fidelity 0.78), discounted because it is an engineering sufficiency proof leaning on supervision and detection that REE does not get for free.
