## 2. Method

- **World head training (2 arms per seed):** `w3_l2r_member_probe.py`'s exact recipe (`E2WorldMember` via `WakingTrainer`, W2a `StructuredBabbler` over 12 Phase-0 episodes into the FROZEN retained set, 3000 pre-updates, then 1200 native closed-loop on-policy steps at 8 member updates/step, 25% retained replay, re-encoded). **real** arm: unmodified. **shuf** arm: retained babbling actions relabelled by the fixed permutation `PERM = [1,2,3,4,0]` immediately after babbling, everything else identical (byte-identical to `w3_l2r_member_probe.py --arm shuf`). **untrained**: `ref`'s own construction (`rollout_fidelity_probe.build_B`), i.e. the `e2.world_transition` / `world_action_encoder` weights BEFORE any `E2WorldMember` update. Seeds 106-110.
- **Held-out states + env ground truth, one integrated pass (`gen_policy_env`):** reimplements `BB.gen_policy(seed, 20, 300, BB.pol_uniform(seed*11+17))` action-for-action (same policy draws, same env creation, same reset-on-done), additionally deep-copying the env right after each segment's own `reset()` (before that segment's first action) -- this consumes no extra RNG, so the resulting segments are derived identically to `gate_c_probe.py`'s own `te_segs`. Per segment: `t_pick` drawn from `default_rng(seed*97+5)` (same formula, same order, skipping zero-length segments -- identical to `gate_c_pool_controls_probe.py`); `ref.sense()` run in order up to `t_pick` (capturing `z0`, `s0`, the live `LatentState`) and one tick further where available (for the P3 validation). The exact live env state at `t_pick` is reconstructed by replaying that segment's OWN recorded actions onto the segment-start snapshot -- not a fresh/independent env, so no drift is possible.
- **Predicted step-1 growth**, per state, per class c in {0..4} (4 = "stay", `structured_babbling.py`): `g1_pred(head) = ||ref.e2.world_forward(z0, onehot(c))|| / ||z0||`, computed separately for the `real`, `shuf` and `untrained` heads (state derivation and env ground truth are shared across all three -- E2's world head plays no role in `sense()`'s encoder path, so `z_true` does not depend on which head is loaded).
- **True step-1 growth**, per state, per class: for each of the 5 classes, deep-copy the reconstructed env-at-`t_pick`, step it with that class, and encode the true next obs side-effect-free via `experiments/_lib/coupled_acceptance.encode_next_side_effect_free(ref, obs_next, lat_at_pick, onehot(c))` (I1 instrument 2's own method). `g1_true(c) = ||z_true(c)|| / ||z0||`.
- **State attribution:** Spearman correlation (reusing `coupled_acceptance.spearman`) between per-state max-over-class `g1_real` and (i) `||z0||` directly, (ii) a nearest-neighbour-in-norm distance from the training-time on-policy `z_world` norm pool (recorded for free during the real arm's 1200-step post-phase). Also the worst state's `||z0||` percentile against that same training-time norm pool.
- Script: `probes/u3/u3_step1_attribution_probe.py` (committed alongside this record). Raw per-seed JSON: `probes/u3/u3_s{106,107,108,109,110}.json`. `n_states=20` outer episodes per seed (matching `gate_c_pool_controls_probe.py`'s default), yielding 166-183 held-out states per seed (early-terminated segments, as in every prior record using this protocol).

The secondary distance metric (nearest-neighbour distance from the training-time norm pool) correlates positively but more weakly (0.55-0.68) -- a less clean version of the same signal, since it is really the RAW small norm, not "distance from the training distribution" in a direction-sensitive sense, that predicts the spike.

**(B) ACTION CLASS -- NOT a driver.** Per-class max g1 (real head) spans only a 0.012-0.033 range across all 5 classes within any seed (e.g. seed 106: 1.698-1.719; seed 110: 1.704-1.716), and per-class medians are within 0.005-0.006 of each other. The worst class is DIFFERENT in every seed (0, 3, 3, 4, 1) -- no class, including "stay" (4, which IS the worst class in seed 109 but squarely mid-pack elsewhere), is a systematic outlier. The growth spike is a property of the STATE, expressed near-identically regardless of which of the 5 actions is queried from it.

**(C) TRAINING -- training tempers but does not remove the spike, and REAL vs SHUF are nearly indistinguishable.** `untrained` (ref's own construction, before any `E2WorldMember` update) shows a MUCH larger max growth (2.90-3.75) than either trained arm (1.71-1.74) -- so training clearly reduces the effect. But `real` and `shuf` -- which differ only in whether the retained replay's action labels are the true ones or a fixed relabelling -- land within 0.01-0.02 of each other on every seed (e.g. seed 106: 1.7187 vs 1.7076; seed 108: 1.7271 vs 1.7251). If the spike were a defect specific to what the head LEARNED about action-conditioned dynamics, training on scrambled action labels should look different from training on correct ones; it does not.

**(D) TRUTH -- the environment's own true step-1 growth reaches the SAME magnitude, and slightly EXCEEDS the predicted growth on every seed.** `true` max g1 (1.7273-1.7683) is >= `real` max g1 (1.7132-1.7385) in all 5 seeds. `corr(real, true)` across every (state, class) pair is strongly positive (0.892-0.926) in every seed. The single worst REAL cell in every seed has a TRUE growth within 0.01-0.05 of the predicted value (e.g. seed 106: g1_real=1.7187, g1_true=1.7006; seed 110: g1_real=1.7155, g1_true=1.7139). **This means the "spike" is not the trained head inventing instability: the real encoder (`world_obs_encoder`/`latent_stack`, untouched by W3's E2WorldMember training) genuinely produces a ~1.7-1.8x jump in ||z_world|| between two consecutive real ticks, at exactly the same small-||z0|| states, independent of E2 entirely.**

Instrument validation (P3): `max_abs_diff = 0.0` on every one of 158-172 validated states per seed, 5/5 seeds -- the cloned-env-and-branch method used for (D) reproduces the live `agent.sense()` path exactly, not approximately.

## 4. Verdict: MIXED, weighted CORRECT-PREDICTION + RATIO-ARTEFACT; explicitly NOT HEAD-DEFECT

None of the four candidate verdicts fits cleanly alone; two of the three fit together and the third is ruled out:

- **NOT HEAD-DEFECT.** A defect in the trained E2 world head specifically would show INFLATED growth relative to ground truth, concentrated on a class or state region the head handles badly, and would differ visibly between the real-labelled and scrambled-labelled training arms. None of that is true: `real` growth is at or slightly BELOW `true` growth (never meaningfully above it, sec 3D), the effect is state-driven with no class signature (sec 3B), and `real` vs `shuf` are nearly identical (sec 3C).
- **CORRECT-PREDICTION, largely.** The trained head's step-1 prediction tracks the true encoder's own next-state norm closely (corr 0.89-0.93 pooled over all state x class pairs, worst-cell agreement within 0.01-0.05) -- when the true dynamics genuinely jump by ~1.7x at a given tiny-||z0|| state, the head correctly predicts that jump, for every action class queried from it. This is evidence FOR the head, not against it.
- **RATIO-ARTEFACT, in the sense that matters for the gate's statistic (not in the sense of "the predictor is fooled by a small denominator" -- it is not fooled; the ratio itself is what is unstable at a small denominator).** The spike is not a training defect but it IS a genuine property of dividing by `||z0||` when `||z0||` is near the floor of the observed distribution (worst-case states sit at the 0th-1st percentile of the training-time norm pool, sec 3A). Because it reproduces in BOTH the predicted and the TRUE next-state norms, at the SAME extreme-small-denominator states, it reads as the encoder's own EMA-based scale (`SD-008`, alpha_world 0.3, per `w6a_world_encoder_member_build_20260925.md`'s own finding that the untrained sensed z_world is "already effectively one-dimensional" near this alpha) occasionally producing a near-collapsed ||z_world|| at one tick, from which ANY next tick's encode -- true or predicted -- returns to something closer to the encoder's typical operating scale (training-time mean ||z_world|| 0.42-0.52 per seed here), which is a large RELATIVE jump purely because the starting scale was small, not because the destination is unusually far in absolute terms (the worst cells' absolute norms stay well inside the encoder's ordinary range; only the RATIO is extreme).

**Which statistic each verdict would argue for (per the brief; U1 in `asp_gate_c_readout_20260925.md`/`gate_c_pool_controls_20260925.md`, not decided here):** if the finding were read as pure CORRECT-PREDICTION with no artefact component, that argues the design's literal all-step-max/1.05 bound (U1a) is simply the wrong bound for this horizon and should be revised upward or replaced, since the growth is real and not a bug. If read as pure RATIO-ARTEFACT, that argues the bound itself is fine but should exclude (or use a floored/normalised denominator for) near-collapsed ||z0|| states -- a state-conditioned exception, not a global bound change, and specifically NOT U1c's "shorten the horizon" (sec 3's step-1 concentration means shortening the horizon captures the same failure, unchanged, at any H >= 1). Given the MIXED reading here (both components present, and the true dynamics show the SAME pattern the predictor does), this record's own lean is that the finding argues AGAINST U1a as currently specified (a literal bound that fires even on the environment's own true dynamics is measuring something other than head instability) and TOWARD a state-conditioned exception or U1b (late-window mean, which this and every prior record in this line found already passes comfortably) -- but the choice remains the orchestrator's/user's, not this probe's.
