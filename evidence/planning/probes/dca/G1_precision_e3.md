## 0. The default-config control path through E3 (what actually runs)

1. `ag.update_residue(harm)` (driver-called, after env.step) -> `e3.post_action_update` (ag:12213; the ONLY caller in
   ree_core -- `grep -rn "post_action_update(" ree_core`) -> `update_running_variance` (e3:4942-4947) -> rv EMA
   alpha 0.05 (e3:1113-1116).
2. Next E3 tick: `e3.select` computes `committed = rv < 0.40` (e3:4246-4250; threshold cfg:1308, every modulation is
   zero at defaults: MECH-108 sweep off `breath_period=0` cfg:4064/clk:102; SD-011 `urgency_weight=0.0` cfg:1650;
   SD-093 flag off goal.py:300; ARC-029 bar off cfg:1542).
3. `committed` switches the SELECTION RULE: hard argmin (e3:4665-4666) vs `torch.multinomial(softmax(-scores/T))`
   (e3:4688); T = driver kwarg (default 1.0, ag:12028), unmodified at defaults (noise floor / entropy floor /
   phasic burst all None, ag:10282-10380).
4. `committed` -> `beta_gate.elevate()` + `clock.phase_reset()` on entry (legacy non-bistable path, ag:11372-11430;
   `beta_gate_bistable=False` cfg:4074), release otherwise (ag:11432-11435).
5. `committed` -> installs `_committed_trajectory` (e3:4739-4747) -> extra commit-gated residue deposit on harm
   (e3:4955-4959) -> torn down at end of the same post_action_update (e3:5199).

Key structural consequences (D0):
- **rv only moves if the driver calls `update_residue`.** ~392 of 735 experiment scripts that call act/select_action
  call update_residue (`grep -l`). Without it rv stays at precision_init 0.5 > 0.40 forever -> permanently
  uncommitted (T-sampled). So the commit REGIME at defaults is decided by the harness call pattern.
- **With it, commitment is absorbing:** cfg:1291-1306 records measured trained rv ~1e-6..1.6e-5, five orders below
  0.40; `committed_step_fraction=1.0000` even at sweep amplitude 0.999 (GFLAG-0346). Absolute threshold on a learned
  quantity = ARC-155 shape.
- **The rv "PE" is not a clean one-step PE.** `actual_z_world = self._current_latent.z_world` (ag:12211) is the PRE-step
  latent (drivers call update_residue after env.step without re-sensing, e.g. experiments/v3_spark_multienv_transfer.py
  :145-172), and the reference is `world_states[1]` of the trajectory chosen at the LAST E3 tick (e3:4749, 4942-4945),
  held for up to e3_steps_per_tick-1 steps. So on the E3 tick the "PE" is z(t) - pred z(t+1) (predicted step magnitude),
  one tick later it is a true one-step PE, then multi-step drift against a stale prediction. (Flag for D1 check.)
- **Beta elevation changes no action at defaults** (see row B2). MECH-090 trajectory stepping between E3 ticks is dead
  whenever update_residue runs (post_action_update tears `_committed_trajectory` down every step, e3:5199; ag:8627-8652).
- **Every variability controller that could pull the agent out of commitment actuates softmax temperature**, which the
  committed branch (argmin) ignores -> disconnected precisely in the committed regime (ARC-156-like shape).
