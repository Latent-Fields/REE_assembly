## Headline answers

**(1) At DEFAULT config, does anything endogenous change a learning rate, write permission, retention/eviction, or sleep entry within a lifetime? -- NO.**
- LR: no optimizer exists at defaults (every `torch.optim` construction in ree_core is behind a default-OFF master or is a harness-called method; `WakingTrainer` is None, ag:3709-3712). No lr anywhere is modulated at defaults.
- Write permission: the only write-permission switch on a live memory, `e1._offline_mode` (e1_deep.py:1008, :1594), is toggled only by `enter_offline_mode`/`exit_offline_mode` (ag:14033-14062), whose only in-core callers are the sleep-mode methods (ag:14086, :14099) reached only via the default-OFF sleep loop -- and at defaults E1 context-memory writes do not happen anyway (`sd016_writepath_mode="off"`, cfg:804; ag:6635, :12671). MECH-205 surprise-gated writes OFF (cfg:4266).
- Retention/eviction: live stores at defaults are all fixed-capacity FIFO rings (residue RBF ring of 32 centers, field.py:165-180 / cfg:3708; experience/transition/harm-replay buffers trimmed to 1000, ag:7059-7060, :12421-12422). Eviction order = arrival order; no signal modulates it.
- Sleep entry: `sleep_loop` is None at defaults (cfg:7446, ag:3178); `run_sleep_cycle` has no in-core caller except `SleepLoopManager` (pm:592). No sleep ever occurs.
- The one within-life memory change at defaults is the residue ring write, fired by the ENV harm signal (`harm_signal < 0`, ag:12363-12375) with a fixed non-gradient rule -- exogenous trigger, not a controller.

**(2) Is there ANY endogenous code path (main or branch) that can freeze/unfreeze retained memory, reopen plasticity, or start/stop babbling?**
- **Freeze/unfreeze retained memory: NONE, on either tree.** BRANCH `E2WorldMember` retained set is append-only/FROZEN with no unfreeze code (BR:wt:344-358, `_retain` BR:wt:502-509 only appends or counts `retained_dropped`); its source is switched only by `WakingTrainer.set_e2_world_source` (BR:wt:771-780) / `append_external` / `schedule_external` (BR:wt:524-542), and the only callers are harness/tests (BR:experiments/v3_exq_1108...:548, :578; BR:tests/contracts/test_w3_e2_world_member.py:207,345,387). `gated_policy.crystallize()` and `residue_field.snapshot_ewc_anchor()` are called only by an experiment's phase-3 callback (experiments/v3_exq_610e...:505,511). Zero ACh / acetylcholine code in either ree_core (grep `acetylcholin|\bach_|unfreeze` -> only selection_entropy_floor's "There is no unfreeze()"). W2b is NOT built (BR:wt:356 "W2b's UNFROZEN state is not built here").
- **Start/stop babbling: NONE endogenous.** `StructuredBabbler` is constructed when `structured_babbling_enabled` but "nothing in ree_core calls it" (structured_babbling.py:24-28; grep of both trees: consumers only in `experiments/v3_exq_1108...` and tests). The harness picks the epoch (12 fixed episodes, BR:exq_1108:547-578) and also mutates `tr.every_k = 10**9` then `= 1` (BR:exq_1108:549, :579).
- **Reopen plasticity / LR: exists only default-OFF and only in SLEEP.** SD-PP-4 provenance-conditioned gain scales the per-step lr of the e2_world consolidation optimizer by an endogenous replay-provenance gain (cross_module_consolidation.py:241-246; provenance_gain.py rule) -- the ONLY endogenous lr modulator found in ree_core. MEL consumer scales the NUMBER of offline steps by waking E3 PE load (mel:253-285). No waking lr is ever modulated by an agent signal (all `WakingTrainer` member lrs are fixed Adam lrs, wt:354; BR:wt:746).
- **Endogenous sleep START paths exist, default-OFF:** MEL need arm, entry-pressure arm (pm:286-411), MECH-286 permit gate (sleep_onset_gate.py). With sub-knob defaults two of these are degenerate and one is permanently blocked without staleness (see rows 23-25).
