## 1. Design (pre-registered)

**Development, per seed (identical to probe C / N5 phase 1):** `build_B` agent (`world_dim` 32 = deployed, `alpha_world` 0.3), all four reset-init knobs ON, W3 `E2WorldMember` (lr 3e-4, batch 32, MSE, grad_clip 1.0, retained 5000, `reencode`), W2a babbling 2400 steps -> frozen retained set, 3000 member updates, then the S1 native closed-loop dose (1200 `StepHarness` steps x 8 member updates). The dose runs the native codec proposer.

**Training states:** **U** = the fresh agent (reference encoder, no babbling, no member updates) snapshotted before development; **T** = the S1 snapshot. W3 disc4_h1 recorded for both (covariate, not a seed filter).

**Arms (12 lives per seed):** training {U, T} x proposer {**NAT** native codec CEM, **ASPE** `stratified`, **ASP0** `stratified_uniform`} x commitment {**NATc** native gate (rv vs 0.40), **OFF** forced uncommitted: `e3.config.commitment_threshold = -1` set every tick before selection, as probe C's FS}. ASP is switched on the life's deep copy; `HippocampalModule._validate_action_space_proposal_config` is called on it and raises on any exclusive-flag conflict. The **primary cell is T-NAT-OFF** (probe C's FS condition).

**Test lives:** one continuous life of **400 ticks** per arm, fresh 12x12 phase-0 env (probe C's `make_life_env(150)`, `max_episode_steps` 500), health pinned at 1.0 around every step (no death resets; a `done` is logged and reset), trainer frozen, identical env seed / torch / numpy RNG across the 12 lives of a seed. No ticks excluded (there is no world change to time-lock to).

**Seeds (registered, run in this order):** **781, 782, 783, 784, 785** (fresh; not 0-2, 106-110, 531-535, 611-615, 721-725, 761-765, 790, 798, 799). Minimum 3; if the ~2 h compute cap bites, the verdicts are reported over the seeds completed, labelled INTERIM, with >= ceil(0.6 n) applied to that n.

**Per-E3-tick readouts** (the pool E3 actually scored, identified by object identity with `agent._committed_candidates`; simulation-mode selects are ignored):
- **P** (proposals): per candidate the first-step vector, its class (argmax), source tag; the pool's class histogram. **P0** (native only): the iteration-0 pre-refit class counts from `_last_propose_diagnostics["cem_iteration_diagnostics"][0]` = the raw decoder cloud before any score-driven refit.
- **Pc** (decode counterfactual): classes of the same first-step vectors after subtracting the pool mean vector (centred argmax), and the fraction of candidates whose class equals the argmax of the pool-mean vector (`agree`). Also per-dimension mean / SD, median pairwise L2 distance and median norm of the first-step vectors.
- **SC** (scoring): E3's post-bias `scores`, the effective temperature T actually passed to `select`, `probs = softmax(-scores/T)` (cross-checked against `e3.last_precommit_probs`), the softmax **class mass** m_c = sum of probs over candidates of class c, the within-tick candidate entropy and perplexity/K, score SD and range/T.
- **SHUF** (control): the class mass with probs permuted over candidates (64 permutations per tick, averaged). If scoring carried no class preference, SC would equal SHUF.
- **SEL**: the selected candidate's class and E3's `committed` flag; **ARGMIN**: the lowest-score candidate's class.
- **EXEC** (every tick): the class the env received (after beta stepping / hold / freeze overrides), beta-elevated state, whether the agent's cell changed (moved), and the step's harm signal.

**Stage entropies (bits, per life; marginal over the life's E3 ticks):** H_P = entropy of the mean per-tick pool class distribution; H_Pc likewise; H_P0 likewise (native); H_SC = entropy of the mean class mass; H_SHUF likewise; H_SEL = entropy of the selected-class histogram; H_EXEC = entropy of the executed-class histogram over all 400 ticks. Within-tick means are reported alongside. **CEIL** = the uniform-random-class policy = log2 5 = 2.32 bits (the entropy ceiling control; its plug-in value at n = the life's E3-tick count is reported too).

**Decision rule (F = 0.5, fixed here):**
1. Chain CEIL -> P -> SC -> SEL -> EXEC. The **collapse stage** is the FIRST stage whose H < F x H(previous stage).
2. If H_EXEC >= F x CEIL (1.16 bits), the life is **NO-COLLAPSE** (diversity reaches execution) whatever the chain says. If H_EXEC < F x CEIL but no single step falls below F, the life is **GRADUAL(stage with the smallest ratio)**.
3. A P-stage collapse is split: **P/DECODE** iff H_Pc >= F x CEIL and H_P < F x H_Pc (the continuous cloud is diverse around a common offset that the argmax maps to one class); else **P/GENERATOR**.
4. **Scoring-bottleneck flag** (the shuffle control): H_SC < F x H_SHUF.
4b. An EXEC-stage collapse (or GRADUAL(EXEC)) is sub-labelled **/HOLD** iff the modal executed class's mean run length (ticks from its E3 tick to the next E3 tick) is >= 2x the mean run length of all other classes' runs (the executed distribution is re-weighted by how long each choice is held), else **/OTHER**. Per-class run lengths and moved-fraction by class are reported.
5. **Cell verdict** = the collapse stage (P / SC / SEL / EXEC / NO-COLLAPSE / GRADUAL) reached on >= ceil(0.6 n) seeds (3/5), else MIXED (the per-seed list is reported).
6. **Headline verdict** = the T-NAT-OFF cell verdict (earliest stage + domain). The ASP arms are the proposer intervention: if T-NAT-OFF collapses at P and T-ASPE/ASP0-OFF (pool uniform by construction, H_P = 2.32) reach NO-COLLAPSE, the proposer is sufficient to explain the collapse (D2); if the ASP arms instead collapse at SC, scoring is a second, independent bottleneck. The NATc arms locate the commit gate's contribution (SC -> SEL under argmin) and the U arms say whether the collapse is present before any learning.

**What is NOT concluded here:** no fix is chosen or built; no claim moves; the untrained-agent arms say nothing about competence. The rule is applied as written; any readout outside it is labelled descriptive.

### 1a. Calibration disclosure
Seed 798 (not registered) was run as a functional smoke before registering (`results/SMOKE_s798.*`, reduced development: 1 babbling episode, 300 member updates, 200 dose steps; 60-tick lives). It ran every arm without error; the E3-select capture matched the proposer's pool by identity on every E3 tick and the recomputed softmax matched `e3.last_precommit_probs` to < 1e-8. What it changed, before any registered seed:
- **Recording added:** per-tick moved / harm, and the /HOLD sub-label (rule 4b). The smoke showed the E3 cadence is event-driven: runs of E3 ticks on consecutive steps while the agent moves (harm on moves -> phase reset), and ~9-step holds otherwise, and the executed entropy fell below the selected entropy in every OFF life (e.g. T-NAT-OFF H_SEL 1.49 -> H_EXEC 0.81). Without the hold readout that drop could not be attributed.
- **Seen, not acted on (numbers from an under-developed agent, n = 1):** the native pool never contained class 4 and its first-step vectors carried a common per-dimension offset (pool-mean vector ~[0.14, 0.12, 0.10, 0.03, -0.06] with per-dim SD ~0.03-0.04); the centred argmax restored H 2.28 against H_P 1.43. In the untrained agent the score range was ~40-57x the temperature in ASP pools (softmax nearly deterministic); in the smoke-trained agent it was ~2-6x.
- A lock-hygiene fix: the fairness gap is persisted across this worker's processes (`results/.last_release`). A relaunch 80 s after the smoke's release was killed while still WAITING (it never held the lock) and restarted with the fix.
- No window, metric, threshold, arm or seed was changed after the smoke.
